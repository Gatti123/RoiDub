# Yield Desk — калькулятор ROI и PDF-отчёты для брокеров Дубая

Брокер вводит объект, часть данных подставляется из базы (цена за фут по району, аренда, сервисные сборы, условия застройщика), расчёт обновляется на лету, а PDF на английском или русском скачивается одной кнопкой. Отчёт можно отправить клиенту ссылкой в WhatsApp.

Стек: Next.js 14 (App Router), Supabase (Auth, Postgres, Storage), @react-pdf/renderer.

## Запуск за 15 минут

**1. Supabase.** Создайте проект на supabase.com. В SQL Editor выполните по очереди:
- `supabase/migrations/0001_init.sql` — таблицы, права доступа (RLS), бакет для логотипов;
- `supabase/migrations/0002_area_price_change.sql` — поле с фактическим изменением цен;
- `supabase/seed.sql` — застройщики и ставки сборов;
- `supabase/seed_areas.sql` — 23 района: цены, аренда по спальням, сервисные сборы.

**2. Переменные окружения.** Скопируйте `.env.example` в `.env.local` и заполните значения из Supabase → Project Settings → API. `SUPABASE_SERVICE_ROLE_KEY` нужен только для публичных ссылок `/r/<token>`; держите его в секрете и никогда не добавляйте префикс `NEXT_PUBLIC_`.

**3. Локально.**
```bash
npm install
npm run dev
```
Откройте http://localhost:3000, создайте аккаунт, заполните профиль и загрузите логотип.

**4. Деплой на Vercel.** Импортируйте репозиторий, добавьте те же четыре переменные окружения, в `NEXT_PUBLIC_SITE_URL` укажите адрес сайта. В Supabase → Authentication → URL Configuration пропишите этот адрес как Site URL.

## Как устроено

```
app/
  login/                 вход и регистрация
  profile/               данные брокера и логотип для отчётов
  calculations/          список, новый расчёт, редактирование
  api/report/[id]/       PDF для брокера (скачивание, только свои расчёты)
  r/[token]/             PDF по публичной ссылке для клиента
components/Calculator.tsx  форма, живой пересчёт, сохранение, PDF, WhatsApp
lib/calc.ts                движок расчётов (общий для браузера и PDF)
lib/pdf/Report.tsx         макет отчёта
lib/i18n.ts                все тексты EN/RU
supabase/                  схема и данные
scripts/pdf-preview.tsx    рендер тестовых PDF без базы: npx tsx scripts/pdf-preview.tsx
```

PDF всегда пересчитывается на сервере из сохранённых вводных, поэтому отчёт совпадает с движком даже после правок формул.

## Логика расчётов

**Расходы на вход.** Вторичка: 4% DLD, административный сбор, трасти-офис + НДС, комиссия агента 2% + НДС, при ипотеке регистрация залога. Первичка: 4% DLD (можно отметить, что платит застройщик) и административный сбор, комиссии покупателя нет.

**План платежей (первичка).** Брокер вводит два числа: первый взнос и сколько процентов платится до сдачи (например, 20 и 60 для плана 60/40). Приложение делит промежуточную сумму на равные ежемесячные платежи до сдачи, остаток приходится на сдачу. Пост-хэндовер планы и нестандартные графики пока не поддерживаются.

**Переуступка до сдачи (первичка).** Вложено = выплаты к месяцу продажи + сборы на входе. Прибыль = премия − NOC − плата за переуступку − комиссия агента − исходные сборы (4% DLD не возвращаются). Если оплачено меньше порога застройщика, показывается предупреждение.

**Аренда.** Чистая аренда = аренда × (1 − простой) − сервисные сборы − обслуживание − управление. Показываются валовая и чистая доходность, при ипотеке — денежный поток и доходность на собственные средства. Для первички аренда начинается после сдачи.

**Владение и продажа через N лет.** Помесячные денежные потоки (платежи, аренда, ипотека, продажа) и годовая доходность по IRR, чтобы сравнивать сценарии с разным графиком вложений честно.

## Данные по районам

Все данные по районам лежат в `scripts/build_area_data.py`. Скрипт выпускает две вещи: `supabase/seed_areas.sql` для базы и `data/yield-desk-area-data.xlsx` для проверки (с источником по каждой строке). Чтобы обновить данные, поправьте числа в скрипте, запустите `python3 scripts/build_area_data.py` и выполните новый `seed_areas.sql` в Supabase.

**Откуда цифры (ноябрь 2026):**
- Цена за фут и аренда по спальням для 21 района — Property Monitor, зарегистрированные в DLD сделки вторичного рынка и договоры аренды, 2026 год по состоянию на начало апреля.
- DSO и International City — Bayut (цены и аренда из объявлений, H1 и Q3 2026).
- Сервисные сборы — медианы утверждённых бюджетов RERA (DLD/Mollak) за 2026 год, где они опубликованы; остальное — оценки из обзоров, помечены «est.».

**Важно:**
- Аренда по DLD включает продления договоров, поэтому она ниже, чем в объявлениях на Bayut. Это осознанно консервативная база.
- Прогноз роста по умолчанию — фактическое изменение цен (2026 к 2025), ограниченное диапазоном от −2% до +3% в год. Потолок низкий, потому что в третьем квартале 2026 цены по городу были на 1,7% ниже, чем годом ранее. Фактическое изменение показывается брокеру подсказкой под полем.
- Ячейки с жёлтой заливкой в таблице — оценки, их стоит сверить в первую очередь.

## Телеграм Mini App (@DubaiRoiBot)

Брокер работает только через бота: нажимает «Калькулятор», вход происходит автоматически по его Телеграм-аккаунту, без почты и пароля. При первом входе открывается профиль: имя (подставляется из Телеграма), телефон, агентство и логотип по желанию. Кнопка «Отправить PDF в Телеграм» присылает отчёт в чат с ботом, оттуда его можно переслать клиенту. Ссылка для WhatsApp тоже работает.

Вход по почте на сайте оставлен для вас: тестировать и администрировать с компьютера.

### Настройка (один раз)

1. **Новый токен.** Старый был показан в чате: в @BotFather отправьте `/revoke`, выберите бота, сохраните новый токен.
2. **Supabase:** выполните `supabase/migrations/0003_telegram.sql`.
3. **Vercel → Settings → Environment Variables**, добавьте две переменные и сделайте Redeploy:
   - `TELEGRAM_BOT_TOKEN` — новый токен;
   - `TELEGRAM_WEBHOOK_SECRET` — любая длинная случайная строка (например, сгенерированная менеджером паролей).
4. **Подключите бота к приложению** (с вашего компьютера, в папке проекта):
   ```
   TELEGRAM_BOT_TOKEN=новый_токен TELEGRAM_WEBHOOK_SECRET=та_же_строка NEXT_PUBLIC_SITE_URL=https://ваш-адрес.vercel.app node scripts/telegram-setup.mjs
   ```
   Скрипт настроит ответ на /start, кнопку меню «Калькулятор», описание бота. Все пять строк должны закончиться на `ok`.
5. Откройте бота в Телеграме, нажмите «Старт» → «Открыть калькулятор».

### Как это устроено

- `lib/telegram.ts` — проверка подписи Телеграма (initData) и вызовы Bot API.
- `app/api/tg/auth` — проверяет подпись, создаёт пользователя при первом входе, ставит сессию Supabase.
- `app/api/tg/send/[id]` — собирает PDF и отправляет его брокеру в чат.
- `app/api/tg/webhook` — отвечает на /start кнопкой открытия калькулятора.
- Cookies выставлены с `SameSite=None; Secure`, иначе в Телеграм Web/Desktop (окно внутри iframe) сессия не сохраняется.
